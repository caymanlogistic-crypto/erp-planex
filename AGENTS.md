# AGENTS.md — входной файл для ИИ-агентов

## Ты работаешь в проекте ERP PLANEX

ERP PLANEX — ERP-система для управления логистическими перевозками.
Разработка ведётся ИИ-агентами. Основной кодер: KILO + DeepSeek.

## Обязательная последовательность перед началом работы

1. Прочитай `docs/ai/ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md` — главный переносимый контекст проекта.
2. Прочитай `docs/ai/PROJECT_STATUS.md` — пойми текущий этап.
3. Прочитай `docs/ai/DECISIONS_LOG.md` — изучи все утверждённые решения.
4. Прочитай `docs/ai/AGENT_WORK_LOG.md` — узнай, что уже сделано.
5. Прочитай профильные документы из `docs/architecture/`, `docs/business/`, `docs/ui/`, относящиеся к твоей задаче.

## Правила работы

- **Не придумывай** бизнес-правила, роли, юридические требования, бухгалтерскую логику.
- **Обновляй логи** после каждой задачи в `docs/ai/AGENT_WORK_LOG.md`.
- **Обновляй статус** проекта в `docs/ai/PROJECT_STATUS.md`.
- **Завершай задачу** только через FINAL REPORT со статусом.
- **Архитектурные решения** записывай в `docs/ai/DECISIONS_LOG.md`.
- **Любые изменения статуса** фиксируй в `docs/ai/PROJECT_STATUS.md`.
- Если данных недостаточно — ставь статус `NEEDS_OWNER_DECISION` и останавливайся.
- Бизнес-код не пиши без отдельного задания.
- Не меняй утверждённую архитектуру без записи решения.

## Обязательное правило переносимого контекста

`docs/ai/ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md` — главный живой файл для переноса контекста проекта между ChatGPT-чатами.

Перед завершением любой задачи агент обязан проверить, нужно ли обновить этот файл.

Файл обязательно обновляется, если изменились:
- текущий этап проекта;
- текущий фокус;
- следующий шаг;
- архитектурное решение;
- бизнес-правило;
- структура папок;
- список ключевых файлов;
- git commit hash;
- правила агентов;
- правила логирования;
- модель БД;
- модель ролей;
- feature toggles;
- deployment;
- запреты или обязательные проверки;
- результат важной задачи;
- любые решения владельца проекта.

Агент обязан добавлять в файл новую важную информацию и удалять или заменять устаревшую. Запрещено оставлять файл неактуальным.

Если файл не обновлялся, в FINAL REPORT нужно явно указать причину.
