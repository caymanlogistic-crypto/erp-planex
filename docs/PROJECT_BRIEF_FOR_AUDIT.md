# ERP PLANEX — краткое вводное для независимой оценки

Дата подготовки: 2026-07-14

## Что это за система

ERP PLANEX — веб-система для управления экспедиторской компанией. Проект работает в папке `/erp` на PHP 8.3 + MySQL 5.7 и разделяет данные центральной панели суперадминистратора и рабочих баз компаний-экспедиторов.

Главная идея архитектуры: суперадмин создаёт юридическое лицо/экспедитора, система назначает ему отдельную рабочую БД из пула, а руководитель экспедитора дальше управляет пользователями, справочниками, документами, рейсами, исполнителями и финансовыми выписками.

## Основные роли

- `superadmin` — управляет компаниями, пулом БД, созданием руководителя и диагностикой.
- `company_owner` — руководитель компании, управляет пользователями, настройками и рабочими данными компании.
- `senior_logist` / `logist` — операционные роли для работы с клиентами, рейсами, исполнителями, водителями и транспортом.

## Ключевые функциональные зоны

- Создание и редактирование юридического лица через единый модуль.
- Реестр экспедиторов/компаний в суперадминке.
- Пул рабочих баз данных для компаний (`spugovxsim_1` ...), с отображением использования.
- Управление руководителем и пользователями компании через унифицированные модальные формы.
- Документы юридического лица: загрузка, просмотр, замена и удаление.
- Справочники компании: клиенты, подрядчики, водители, транспорт, исполнители рейса.
- Финансы: банковские счета, импорт XLSX-выписок ВТБ вручную и через IMAP/cron.

## Как должен работать импорт выписок

Руководитель компании задаёт IMAP-настройки почты и банк. Сейчас реализован ВТБ.

Скрипт:

```bash
scripts/import_bank_statements.php
```

Должен запускаться по cron, читать письма от `vtb-inform@vtb.ru`, находить XLSX-вложения ВТБ, парсить операции и дневные балансы, дедуплицировать импорт по SHA-256 файла и сохранять данные в локальную БД компании.

Важное runtime-исправление от 2026-07-14: письма ВТБ на SpaceWeb могут лежать не в plain `INBOX`, а в дополнительной IMAP-папке. Поэтому импортёр обязан сканировать все IMAP-папки, не зависеть от статуса `UNSEEN`, и использовать folder-aware `source_uid`.

## Дизайн и UX

Проект использует собственную дизайн-систему:

```text
public/assets/css/erp-ui.css
docs/ui/DESIGN_STANDARD.md
```

Ожидаемый стиль: плотные рабочие ERP-интерфейсы, компактные таблицы, модальные формы по паттерну формы водителя, без случайных inline-style и без второго UI-kit.

## Что важно проверить аудитору

- Архитектуру разделения центральной и локальных БД компаний.
- Безопасность работы с IMAP-паролями и `.env`.
- Корректность дедупликации банковских выписок.
- Надёжность cron/CLI-скриптов на shared-хостинге.
- Единообразие UI/UX модальных форм и таблиц.
- Отсутствие жёстко зашитых секретов в коде.
- Качество маршрутизации и контроля доступа по ролям.
- Технический долг в локальных миграциях, особенно старые warnings `016_rename_vehicles_to_vehicle_units.sql` и `034_drop_drivers_phone_unique.sql`.

```bash
php -l scripts/import_bank_statements.php
php -l app/Service/BankStatementImapImporter.php
git diff --check
```
