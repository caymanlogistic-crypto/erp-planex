# ERP PLANEX — AGENT_LOGGING_MASTER_PROMPT

## Главный принцип

ERP PLANEX разрабатывается с помощью ИИ-агентов. Каждый агент обязан вести подробный MD-лог своей работы.

Цель логирования: любой новый агент должен за 5–10 минут понять:
- на каком этапе находится проект;
- какие решения уже приняты;
- что сделано;
- что проверено;
- что не сделано;
- какие есть блокеры;
- какие файлы были изменены;
- что делать дальше.

Запрещено оставлять важную информацию только в чате.

---

## Обязательные файлы

Перед началом работы агент обязан прочитать:

```text
docs/ai/ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md
docs/ai/PROJECT_STATUS.md
docs/ai/DECISIONS_LOG.md
docs/ai/AGENT_WORK_LOG.md
docs/ai/AGENT_NETWORK.md, если задача связана с KILO, ролями, промтами или агентным циклом
docs/ui/DESIGN_CODE_INTEGRATION.md, если задача связана с UI или дизайн-кодом
```

Также агент читает профильные файлы по задаче:

```text
docs/architecture/
docs/business/
docs/ui/
```

После работы агент обязан обновить:
- `docs/ai/AGENT_WORK_LOG.md`;
- `docs/ai/PROJECT_STATUS.md`;
- `docs/ai/DECISIONS_LOG.md`, если принято решение;
- профильные MD-файлы, если изменились архитектура, бизнес-логика, UI или правила.
- `docs/ai/ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md`, если изменился переносимый контекст проекта.

---

## Обязательное правило переносимого контекста

`docs/ai/ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md` — главный живой файл для переноса контекста ERP PLANEX между ChatGPT-чатами.

Каждый агент перед завершением задачи обязан проверить, нужно ли обновить этот файл.

Файл обязательно обновляется, если изменилось хотя бы одно из следующего:
- текущий этап проекта;
- текущий фокус;
- следующий шаг;
- архитектурное решение;
- бизнес-правило;
- структура папок;
- список ключевых файлов;
- git commit hash;
- правила агентов;
- правила логирования;
- модель БД;
- модель ролей;
- feature toggles;
- deployment/развёртывание;
- запреты или обязательные проверки;
- результат важной задачи;
- любые решения владельца проекта.

Агент обязан добавлять новую важную информацию и удалять или заменять неактуальную. Запрещено оставлять этот файл устаревшим.

Если агент обновил `PROJECT_STATUS.md`, `DECISIONS_LOG.md`, `AGENT_WORK_LOG.md` или профильные архитектурные/бизнес/UI MD-файлы, он обязан проверить и при необходимости обновить также `ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md`.

Если файл не обновлялся, агент обязан указать причину в FINAL REPORT.

## Запрет на выдумывание

Агентам запрещено придумывать:
- юридические требования;
- бухгалтерскую логику;
- структуру документов;
- роли пользователей;
- бизнес-процессы;
- налоговую логику;
- правила международных перевозок;
- производственные процессы.

Если данных недостаточно, агент обязан:
1. остановиться в спорном месте;
2. явно указать, каких данных не хватает;
3. записать вопрос в лог;
4. поставить статус `NEEDS_OWNER_DECISION`.

## Разделение фактов и предположений

В любой аналитике агент обязан разделять:

```md
## Факты
...

## Предположения
...

## Требует подтверждения
...
```

Предположения нельзя превращать в код без подтверждения владельца.

---

## Правило закрытого цикла

Задача не считается завершённой, если агент просто создал файлы или написал код.

Задача завершена только если:
- изменения внесены;
- документация обновлена;
- проверки выполнены;
- ошибки исправлены или зафиксированы;
- статус задачи записан;
- следующий шаг понятен.

---

## Финальный отчёт агента

Каждый агент завершает работу отчётом:

```md
# FINAL REPORT

## Статус
DONE / PARTIAL / BLOCKED / NEEDS_OWNER_DECISION / NEEDS_QA / NEEDS_REWORK

## Что сделано
...

## Какие файлы изменены
...

## Какие документы обновлены
...

## Какие проверки выполнены
...

## Что не проверено
...

## Риски
...

## Вопросы владельцу
...

## Следующий шаг
...
```

Запрещено завершать задачу словами “всё готово” без логов, проверок и статуса.

## Дополнение по UI-шаблонам страниц

Если задача создаёт или меняет UI-страницу, в `AGENT_WORK_LOG.md` обязательно указать:

- какой MD-шаблон страницы создан/обновлён;
- какой код реализован по шаблону;
- проверял ли QA соответствие шаблону;
- были ли замечания и второй круг.

Если UI-шаблон отсутствовал и задача заблокирована, это фиксируется как `BLOCKED: MISSING_UI_HANDOFF`.
