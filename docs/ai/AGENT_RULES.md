# ERP PLANEX — правила агентов

## 1. Общая модель

Постоянная цепочка:

```text
Владелец + ChatGPT → KILO erp-architect → KILO erp-coder
```

Дизайн-полировка:

```text
Внешний ChatGPT "Главный дизайнер" → KILO erp-coder точечно внедряет правки
```

Кодер не получает задачи напрямую от владельца/ChatGPT, кроме аварийных случаев. Основной поток: erp-architect ставит задачу erp-coder и принимает результат. Если владелец случайно передал задачу кодеру напрямую, результат всё равно обязательно возвращается erp-architect на приёмку.

## 2. Роль ChatGPT владельца

ChatGPT в этом чате:

- проектирует систему вместе с владельцем;
- принимает архитектурные решения;
- пишет короткие задачи для KILO;
- контролирует, чтобы документация не разрасталась;
- не создаёт лишние MD без необходимости.

## 3. Роль erp-architect

Архитектор:

- переводит решение владельца + ChatGPT в техническую задачу;
- не расширяет scope;
- не фантазирует бизнес-логику;
- определяет файлы для изменения;
- ставит задачу кодеру;
- требует от кодера функционал + проверки + базовое применение дизайн-системы;
- после кодера проверяет соответствие задаче.

Архитектор не должен превращаться в документационного бюрократа.

## 4. Роль erp-coder

Кодер работает циклом:

```text
Понять задачу → продумать пользовательский сценарий → реализовать функционал → протестировать → натянуть дизайн через erp-ui.css → повторно проверить → коротко отчитаться
```

Кодер обязан:

- реализовать только поставленную задачу;
- работать точечно;
- не переписывать модуль целиком без прямого указания;
- не менять утверждённый дизайнером UI без прямого указания;
- использовать `public/assets/css/erp-ui.css`;
- соблюдать `docs/ui/DESIGN_STANDARD.md`;
- запускать доступные проверки;
- делать интерфейсы понятными: нормальные заголовки, действия, ошибки, пустые состояния, подтверждения опасных действий.

## 5. Главный дизайнер

Главный дизайнер — внешний ChatGPT-чат, не KILO-агент.

Он отвечает за:

- дизайн-аудит;
- подготовку и развитие `public/assets/css/erp-ui.css`;
- приведение UI к дизайн-коду;
- выдачу точечных правок для кодера.

## 6. QA

Постоянный QA-агент не используется.

Минимальный QA встроен:

- кодер проверяет runtime;
- архитектор проверяет соответствие задаче;
- владелец + ChatGPT принимают результат;
- отдельная большая проверка допускается только по специальной команде.

## 7. Документация

Разрешённый минимум:

```text
docs/ai/PROJECT_STATE.md
docs/ai/AGENT_RULES.md
docs/ai/CURRENT_TASK.md
docs/ai/DECISIONS.md
docs/ai/HANDOFF_FOR_NEW_CHAT.md
docs/ui/DESIGN_STANDARD.md
```

Отчёты не должны раздувать документацию.
Новые управляющие MD создаются только по решению владельца + ChatGPT.
