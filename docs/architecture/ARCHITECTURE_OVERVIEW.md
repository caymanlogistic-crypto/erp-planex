# ERP PLANEX — ARCHITECTURE_OVERVIEW

## Назначение системы

ERP PLANEX — система для получения заявок от клиента и их реализации через подрядчика.

Главная бизнес-цепочка первого этапа:

```text
Заявка клиента
→ договор / документы клиента
→ карточка клиента
→ рейс
→ выбор подрядчика
→ выбор экипажа
→ выполнение линейной перевозки
→ счета / оплаты / закрывающие документы в будущем
```

## Стек

```text
PHP / MySQL
```

## Архитектурный принцип

Система развивается поэтапно и постранично с помощью ИИ-агентов.

Поэтому архитектура должна быть:
- модульной;
- предсказуемой;
- документированной;
- удобной для KILO + DeepSeek;
- расширяемой без переписывания ядра.

## Развёртывание

Код общий, но каждая компания имеет:
- отдельную папку;
- отдельную БД;
- отдельный `/storage`;
- отдельный `.env`.

SUPERADMIN находится отдельно:

```text
erp/superadmin/
```

## Локальная ERP

Одна локальная ERP = одно юридическое лицо.

В локальной ERP есть роль “Руководитель” — админ своей компании.

## Центральная панель SUPERADMIN

SUPERADMIN управляет:
- локальными системами;
- пользователями;
- настройками;
- feature toggles;
- модулями;
- страницами;
- отчётами;
- интеграциями;
- доступностью функционала для конкретных компаний.

## Модульный паттерн

Каждый модуль должен иметь:

```text
feature_code
permission_code
routes
controller
service
repository/model
views
menu item
logs
migrations
checks
MD documentation
```

## Первый этап

Реализуется только линейная перевозка.

Сборный рейс резервируется в архитектуре, но не реализуется.
