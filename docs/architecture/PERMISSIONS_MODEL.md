# ERP PLANEX — PERMISSIONS_MODEL

## Роли верхнего уровня

### SUPERADMIN
Центральный администратор всей платформы.

Имеет максимальный функционал в `erp/superadmin/`.

### Руководитель
Локальный администратор конкретной ERP-компании.

Видит всё внутри своей компании, включая бухгалтерские данные.

### Остальные роли
Будут уточняться по мере проектирования модулей.

Предварительные возможные роли:
- менеджер;
- логист;
- бухгалтер;
- оператор;
- просмотр.

Эти роли пока не являются окончательно утверждёнными.

## Правило доступа

Доступ определяется двумя уровнями:

```text
feature toggle компании
+
permission роли пользователя
```

## Пример действий

```text
view
create
edit
delete
upload_document
verify_document
reject_document
export
approve
```

## Запрет

Нельзя проверять только роль без проверки feature.

Нельзя показывать company-specific отчёт всем компаниям.

## Уточнение 2026-06-13 — экспедитор и локальные пользователи

Экспедитор — это отдельная локальная ERP / компания, создаваемая `SUPERADMIN`.

### Утвержденные роли ближайшего цикла

```text
SUPERADMIN
Руководитель
Логист
```

### SUPERADMIN

Центральный администратор:
- создает экспедитора / локальную ERP;
- запускает автоматическое создание локальной БД и storage-папки;
- отдельным действием создает главного пользователя экспедитора.

### Руководитель

Главный пользователь экспедитора.

Уточнение к прежнему правилу: для onboarding-сценария `Руководитель` хранится в центральной БД SUPERADMIN, привязывается к конкретному экспедитору и после общего логина попадает в локальную ERP этого экспедитора.

### Логист

Локальный пользователь экспедитора.

Хранится в локальной БД экспедитора в таблице `users` и работает только с данными своей локальной ERP:
- клиенты;
- подрядчики;
- транспорт;
- водители;
- связки / экипажи.

**Утверждённая модель Логиста (DECISION-0034, 2026-06-13):**

Таблица: `users` в локальной БД компании (`erp_company_{id}`).

Поля: `full_name`*, `login`*, `password_hash`*, `email`, `phone`, `role_code` (`logist`), `status`.

Пароль: только `password_hash` (bcrypt), открытый пароль в БД не хранится. Временный пароль показывается один раз после создания.

Логин: уникален в пределах локальной БД компании (UNIQUE KEY `uk_login`).

Создатель: Руководитель (`company_owner`) внутри своей локальной ERP.

Доступ: Логист не имеет доступа к SUPERADMIN и к другим компаниям, не может создавать пользователей.

Контекст компании (временный): `?company_id=N` в URL до реализации полноценной авторизации.

### Правило хранения пользователей

```text
SUPERADMIN DB:
- SUPERADMIN users
- главный пользователь экспедитора / Руководитель

Local expeditor DB:
- Логист
- будущие локальные пользователи экспедитора
```

### Утверждённая модель Руководителя (DECISION-0033, 2026-06-13)

Таблица: `company_users` в центральной БД SUPERADMIN.

Поля: `full_name`*, `login`*, `password_hash`*, `email`, `phone`, `role` (`company_owner`), `status`, `comments`.

Связь: `company_id` → `companies.id`, FK ON DELETE CASCADE.

Пароль: только `password_hash` (bcrypt), открытый пароль в БД не хранится. Временный пароль показывается один раз после создания.

Дублирование: один активный Руководитель на компанию (проверка на уровне приложения).

Доступ: Руководитель не имеет доступа к SUPERADMIN и к другим компаниям.

Ответственные: SUPERADMIN создаёт Руководителя отдельным действием после создания компании.
