# ERP PLANEX — PERMISSIONS_MODEL

## Роли верхнего уровня

### SUPERADMIN
Центральный администратор всей платформы.

Имеет максимальный функционал в `erp/superadmin/`.

### Руководитель
Локальный администратор конкретной ERP-компании.

Видит всё внутри своей компании, включая бухгалтерские данные.

### Остальные роли
Будут уточняться по мере проектирования модулей.

Предварительные возможные роли:
- менеджер;
- логист;
- бухгалтер;
- оператор;
- просмотр.

Эти роли пока не являются окончательно утверждёнными.

## Правило доступа

Доступ определяется двумя уровнями:

```text
feature toggle компании
+
permission роли пользователя
```

## Пример действий

```text
view
create
edit
delete
upload_document
verify_document
reject_document
export
approve
```

## Запрет

Нельзя проверять только роль без проверки feature.

Нельзя показывать company-specific отчёт всем компаниям.

## Уточнение 2026-06-13 — экспедитор и локальные пользователи

Экспедитор — это отдельная локальная ERP / компания, создаваемая `SUPERADMIN`.

### Утвержденные роли ближайшего цикла

```text
SUPERADMIN
Руководитель
Логист
```

### SUPERADMIN

Центральный администратор:
- создает экспедитора / локальную ERP;
- запускает автоматическое создание локальной БД и storage-папки;
- отдельным действием создает главного пользователя экспедитора.

### Руководитель

Главный пользователь экспедитора.

Уточнение к прежнему правилу: для onboarding-сценария `Руководитель` хранится в центральной БД SUPERADMIN, привязывается к конкретному экспедитору и после общего логина попадает в локальную ERP этого экспедитора.

### Логист

Локальный пользователь экспедитора.

Хранится в локальной БД экспедитора и работает только с данными своей локальной ERP:
- клиенты;
- подрядчики;
- транспорт;
- водители;
- связки / экипажи.

### Правило хранения пользователей

```text
SUPERADMIN DB:
- SUPERADMIN users
- главный пользователь экспедитора / Руководитель

Local expeditor DB:
- Логист
- будущие локальные пользователи экспедитора
```

Точные поля пользователей и правила паролей не утверждены и должны быть уточнены перед кодингом.
