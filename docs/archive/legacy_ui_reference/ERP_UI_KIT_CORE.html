Compact universal design system

ERP PLANEX UI Kit Core

Compact universal design system derived from STYLE ERP. This file is a visual working catalog for designers, architects, coders and QA. It is not a runtime library and not a component dependency.

Industrial Graphite + Warm Accent desktop-first dense ERP table/form/document/status oriented

Important

ERP_UI_MODULE_CATALOG.html is a legacy extraction draft and extraction history. It was not edited in this task.

Design work now starts from this compact core kit: CORE modules + COMPOSITE patterns + applied examples.

Design principles

no random UI

Industrial Graphite + Warm Accent

Graphite shell, warm copper accent, layered warm surfaces.

Desktop-first ERP

FHD workbench, 224px sidebar, 38px topbar, dense content.

Operational objects

Tables, forms, documents, statuses, inspectors and logs drive screens.

Forbidden look

No SaaS dashboard, landing, Bootstrap admin, demo foundation, random cards.

DESIGNER RULES / CODER RULES / QA RULES

workflow gates

CODER RULESWork only from MD/handoff and this core kit. Do not open STYLE ERP for design choices. Do not invent modules. Unknown/private module in handoff: BLOCKED: UNKNOWN_UI_MODULE.
QA rulesCheck CORE modules, COMPOSITE pattern, visible states, no private/personalized module names in universal handoff. Formal UI QA: PASS is not owner visual acceptance.

PRODUCTION CSS REFERENCE

mandatory for coder

This section contains explicit, non-negotiable production CSS rules. Coder must copy these patterns exactly — no interpretation, no "similar" implementation, no self-made variants.

PANEL RULE (CORE-08).panel must have padding: 0; overflow: hidden;. Internal padding lives in .panel-body only. .panel-head is flush to panel top. Adding padding to .panel when .panel-head or .panel-body are used is a BLOCKER.
KEY-VALUE RULE (CORE-31).kv rows must have border-bottom: 1px solid var(--line-hair). Both dl.kv > dt/dd and div.kv > div > .k markup are accepted. Row dividers are MANDATORY.
NAV HOVER RULE (CORE-02).nav-item:hover { background: var(--nav-hover); color: var(--nav-text-act); } is MANDATORY. Every interactive nav item must have a hover state.
PAGE-HEAD RULE (CORE-05)Official class name is .page-head. If .page-header exists in legacy code, it must be treated as an alias. New implementations must use .page-head.
NAV-DOT (CORE-02 sub-element).nav-dot is an OPTIONAL sub-element of sidebar navigation. If used, it must have the production CSS defined in this Core Kit. If not explicitly in designer handoff, coder must not add it.
ENVIRONMENT-BADGE (CORE-03 sub-element).environment-badge is an OPTIONAL sub-element of topbar. It must only appear if explicitly in designer handoff. Without handoff approval, the badge must not be added or must be removed.
PANEL-HEAD-TITLE (CORE-08 sub-element).panel-head-title is the official sub-element for titles inside .panel-head. Alternatively, h2 may be used (already styled in Core Kit: 12px, 700, uppercase, 0.04em). Coders must not invent alternative title classes.
SOURCE MAPPING RULEEvery page handoff must contain a SOURCE MAPPING table. Each UI element must trace back to its CORE module ID and exact location in this Core Kit. No designer handoff is DONE without SOURCE MAPPING.
CSS COMPATIBILITY RULEBefore adding any child class inside a parent container, coder must check: (1) does parent have padding? (2) must child be flush to edge? (3) where do internal paddings belong? Panel pattern: head flush, body has padding, panel zero padding.
