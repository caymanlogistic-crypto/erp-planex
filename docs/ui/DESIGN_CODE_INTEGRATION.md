# ERP PLANEX — DESIGN_CODE_INTEGRATION

## Назначение

Этот документ описывает, как интегрировать дизайн-код в ERP PLANEX перед началом активной разработки бизнес-модулей.

Цель — заранее задать единый UI-фундамент, чтобы KILO + DeepSeek не создавали разные стили страниц, форм, таблиц и действий.

## Главный принцип

ERP PLANEX — рабочая ERP для сотрудников логистики. Интерфейс должен быть строгим, плотным, понятным и удобным для ежедневной работы.

Это не лендинг и не промо-сайт.

Нельзя начинать массовое написание страниц, пока не определены:
- базовый layout;
- навигация;
- дизайн-токены;
- стандарт кнопок;
- стандарт форм;
- стандарт таблиц;
- стандарт статусов;
- стандарт ошибок;
- стандарт пустых состояний;
- правила подключения CSS/JS;
- место хранения UI-компонентов.

## Что считается дизайн-кодом

Дизайн-код включает:
- HTML-шаблоны layout;
- CSS-переменные и токены;
- базовые компоненты;
- стили форм;
- стили таблиц;
- стили кнопок;
- стили статусов;
- стили уведомлений;
- стили модальных окон;
- простые JS-поведения интерфейса, если они нужны;
- примеры страниц.

## Рекомендуемая структура

Фактическая структура будет создана отдельной задачей. Предварительный стандарт:

```text
public/
  assets/
    css/
      app.css
    js/
      app.js
app/
  View/
    layouts/
      main.php
    components/
      button.php
      input.php
      table.php
      status_badge.php
      alert.php
      empty_state.php
    pages/
```

Если KILO предложит другую структуру, она должна быть обоснована и записана в профильный MD.

## Базовый layout

Первый layout должен предусматривать:
- верхнюю панель или компактный header;
- левую навигацию для модулей;
- рабочую область;
- заголовок страницы;
- основные действия страницы;
- место для уведомлений;
- место для ошибок;
- адаптацию под небольшие экраны без разрушения таблиц и форм.

SUPERADMIN и локальная ERP должны быть визуально различимы, но использовать общий дизайн-фундамент.

## Дизайн-токены

До бизнес-страниц нужно завести единые токены:
- цвета;
- шрифты;
- размеры текста;
- отступы;
- радиусы;
- границы;
- тени, если они нужны;
- цвета статусов;
- состояния hover/focus/disabled/error.

Запрещено задавать произвольные цвета и отступы прямо в каждой странице.

## Компоненты первого этапа

Минимальный набор UI-компонентов:
- `Button`;
- `Input`;
- `Select`;
- `Textarea`;
- `Checkbox`;
- `Table`;
- `StatusBadge`;
- `Alert`;
- `EmptyState`;
- `PageHeader`;
- `FormActions`;
- `ConfirmAction`.

Компоненты должны быть простыми PHP-шаблонами или helper-функциями без сложного фреймворка, пока владелец не утвердит иной подход.

## Стандарт страниц

Каждая рабочая страница должна иметь:
- понятный заголовок;
- главное действие;
- фильтры или поиск, если нужны;
- таблицу, форму или рабочую область;
- видимые статусы;
- пустое состояние;
- понятные ошибки;
- подтверждение опасных действий.

## Стандарт интеграции в PHP

До внедрения бизнес-модулей нужно создать:
1. единый layout;
2. подключение `public/assets/css/app.css`;
3. подключение `public/assets/js/app.js`, если нужен JS;
4. минимальный набор компонентов;
5. одну техническую demo-страницу для проверки дизайна без бизнес-логики.

Demo-страница не должна создавать бизнес-функционал. Её задача — показать layout, кнопки, форму, таблицу, статусы, alert и empty state.

## Правила для KILO при интеграции дизайна

KILO обязан:
- читать все UI-документы перед UI-задачей;
- не создавать отдельные стили для каждой страницы;
- не смешивать бизнес-логику и HTML;
- не писать SQL во view;
- не добавлять страницу без `feature_code` после старта бизнес-модулей;
- обновлять UI-документацию при изменении дизайн-стандарта;
- обновлять `ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md`, если изменился UI-фундамент или структура проекта.

## Что запрещено

- Делать лендинг вместо рабочей ERP.
- Делать разные стили кнопок на разных страницах.
- Использовать случайные цвета без токенов.
- Прятать важные статусы.
- Показывать обычному пользователю технические ошибки.
- Загружать документы в `public`.
- Делать business-specific UI без feature toggle после старта модулей.

## Текущий статус интеграции дизайна

Базовый UI-фундамент интегрирован:
- `public/assets/css/app.css`;
- `public/assets/js/app.js`;
- `app/View/layouts/main.php`;
- `app/View/components/`;
- `app/View/pages/ui_demo.php`;
- `public/index.php` подключает demo-страницу дизайн-фундамента.

Это техническая demo-страница без бизнес-логики, БД, авторизации и маршрутов.

## Следующий шаг интеграции дизайна

Следующая отдельная задача для KILO может быть технической:

```text
Доработать или утвердить базовый UI-фундамент ERP PLANEX:
- проверить layout
- проверить цвета, отступы, компоненты
- при необходимости добавить компоненты
- обновить UI-документы, AGENT_WORK_LOG.md, PROJECT_STATUS.md, ERP_PLANEX_CONTEXT_FOR_NEW_CHAT.md
- выполнить php -l
```

Бизнес-модули после этого писать отдельно.
